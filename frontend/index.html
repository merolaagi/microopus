    What it predicts next

    Each bar is a probability. It came from multiplying your words through every weight matrix in the model, in order.

    The mechanism of action

    1. Look up. Each word becomes a row of numbers copied out of the embedding matrix W_E. That row is the word's starting vector.
    2. Mix across words. Attention lets each word's vector pull information from earlier words. Which words it pulls from is computed on the fly using W_Q W_K W_V W_O.
    3. Transform each word. An MLP multiplies each vector up to 64 numbers and back down with W_up W_down. This is where most stored "knowledge" lives.
    4. Repeat. Steps 2 and 3 form one block. This model stacks 2 blocks. Kimi K2 stacks 61, GPT-3 stacked 96.
    5. Score every word. The final vector is multiplied by W_U to get one score per vocabulary word. Softmax turns scores into probabilities. Pick one, append it, run everything again.

    Weights (the anatomy)

    • Matrices of numbers, stored in a file, loaded into memory once.
    • Identical for every input, every user, every token.
    • Never change while the model runs. Only training changes them.
    • They enter the computation as the right-hand side of a matrix multiply.

    Activations (the physiology)

    • Vectors created from your input, one per token.
    • Flow through the layers, getting multiplied by weights at each stop.
    • Thrown away after the answer, except the attention cache.
    • Everything the model "thinks" about your text lives here, briefly.

    Anthropic hasn't published the architecture or size of Claude Opus, and OpenAI hasn't for its recent GPT models. What is public (the GPT-2 and GPT-3 papers, Llama, DeepSeek and Kimi K2 model cards) is this same decoder-only transformer skeleton. Frontier models differ mainly in scale and refinements such as mixture-of-experts, rotary positions and gated MLPs, all covered in the "Micro to frontier" tab.

    Anatomy: the weight file, opened

    A model checkpoint is a dictionary of named matrices and nothing else. No code, no rules, no text. Here is every tensor in this model. Select one to see every number in it.

    Where the numbers came from

    They started as random noise. Training showed the model 2,500 batches of sentences like "the bird flew over the tree ." and nudged every weight a tiny bit in the direction that lowered its next-word error (the loss). That is the entire training process. Real models do the same with trillions of words.

    Attention patterns

    Each grid is one attention head. Row = the word doing the looking, column = the word being looked at. Darker means more attention. No word can look ahead, which is why the top-right is empty.

    Notice that attention patterns are not weights. They are activations, computed fresh from W_Q and W_K for this particular input. Change the input and the patterns change; the weights that produced them do not.

    Generation: the same weights, over and over

    A model writes one token per pass. Each new token goes back in and the pass runs again, reading the same unchanged weights. Real systems keep a key/value cache so each pass only computes one new row; you can watch it grow below.

    From micro to frontier

    Nothing in a frontier model is structurally stranger than what you just saw. The matrices are wider, there are more blocks, and some layers are split into experts.

    Counting the weights

    Each block has 4 attention matrices of d×d and 2 MLP matrices of d×4d, so roughly 12 × layers × d² weights, plus the embedding tables.

    Every weight is used once per token, as one multiply and one add. So a dense model spends about 2 FLOPs per weight per token.

    Where the weights physically live during a request

    DiskCheckpoint files (often .safetensors shards) hold every matrix by name.
    GPU memoryLoaded once at server start, split across many GPUs. They stay resident for months.
    On-chip memoryFor each matrix multiply, tiles of the weight matrix stream into the chip's fast memory.
    Tensor coresWeight tiles meet activation tiles. Products are summed. The activations move on to the next layer.

    Mixture of experts, in one picture

    Replace the single MLP with many MLPs (experts) and add one small extra weight matrix, the router. The router multiplies the token's vector to score every expert, and only the top few run. Total weights can reach a trillion while each token touches a few percent of them.

    Why batching is cheap

    The expensive part is reading weights from memory. Once a weight tile is on-chip, multiplying it against the vectors of 64 different users' tokens costs little more than doing it for one. That's why providers serve many conversations through the same copy of the weights at once.
